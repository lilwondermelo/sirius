# Кастомная инструкция для коммитов (v2)

Когда я (пользователь) прошу сделать коммит, это означает следующий процесс:

1.  **Анализ**: Я (Gemini) должен проанализировать всю историю нашей сессии.
2.  **Генерация семантики**:
    *   Создать **краткую семантику** коммита (например, `refactor-db-and-dynamic-menu`).
    *   Создать **полное, детальное описание** всех решенных проблем и сделанных изменений.
3.  **Логирование**:
    *   В папке `logs` создать файл с именем `[текущая_дата]_[краткая_семантика].log` (дата в формате `YYYY-MM-DD`).
    *   Записать в этот файл **полное описание**.
4.  **Коммит в Git**:
    *   Выполнить `git add .`.
    *   Выполнить коммит, используя **краткую семантику** как заголовок, а **полное описание** — как тело коммита (`git commit -m "Заголовок" -m "Тело коммита"`).
